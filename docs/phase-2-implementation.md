# Phase 2: реализованный результат

Статус: реализовано и локально проверено 19 июля 2026 года.

## Что теперь можно сделать без изменения кода

Пользователь может создать пустую модель и собрать её на Canvas:

1. создать метрику `Stock`, `Flow`, `Rate` или `One-off`;
2. задать отображаемое название и уникальный технический alias;
3. выбрать единицу, ручное значение и границы `min / max`;
4. написать арифметическую формулу через aliases;
5. протянуть линию от одной карточки к другой и продолжить формулу в
   открывшемся Formula Composer;
6. увидеть автоматически построенные Calculation-связи;
7. назначить любую метрику North Star или оставить модель без неё;
8. собрать метрики в смысловые Domain many-to-many;
9. собрать выбранные карточки в отдельную Visual Group;
10. сохранить несколько независимых моделей, экспортировать и импортировать
    JSON.

Стартовая модель сейчас содержит только 11 узлов денежного потока: доход от
аренды, известные категории расходов, их простые драйверы и прибыль. Предыдущая
расширенная схема при первом запуске сохраняется в локальный backup и
заменяется этим шаблоном.

## Как это устроено простыми словами

Формула хранится не как исполняемый JavaScript, а как проверяемое AST-дерево.
Ссылки внутри дерева ведут на стабильные ID метрик. Поэтому переименование
alias автоматически меняет отображаемый текст формулы, но не разрушает расчёт.

Расчётные связи образуют DAG: перед сохранением система проверяет, что новая
формула не создаёт замкнутый круг. Она также проверяет совместимость единиц и
поведения `Stock / Flow / Rate / One-off`.

Domain и Visual Group решают разные задачи:

- Domain — смысловая классификация; одна метрика может входить в несколько
  доменов;
- Visual Group — геометрическая рамка на Canvas; метрика входит максимум в одну
  такую группу.

## Визуальные правила

- `Stock`: 272 × 224;
- `Flow`: 272 × 136, с переносом формулы;
- `Rate`: 224 × 88 и увеличенное скругление;
- `One-off`: 248 × 104, ticket-стиль, янтарная иконка и пунктирные направляющие;
- зелёная Calculation-линия повышает результат;
- красная понижает;
- серая означает нулевое влияние;
- янтарная означает зависимость, знак которой меняется от значений;
- badge на линии показывает `+`, `−`, `×`, `÷` или смешанную формулу `ƒ`;
- Influence остаётся отдельной пунктирной связью.
- связь автоматически выбирает ближайшую грань карточки: слева, справа, сверху
  или снизу;
- форму всех линий можно переключить на кривую Безье, скруглённую угловую или
  прямую; это только способ отображения, формулы не меняются.

## Сохранение и совместимость

- модели автоматически сохраняются в `localStorage`;
- библиотека поддерживает несколько моделей;
- старая схема v1 мигрирует в v2;
- перед миграцией исходный JSON сохраняется как backup;
- одноразовая замена старого стартового графа также сохраняет его JSON в
  отдельный backup;
- импорт и экспорт используют проверяемый JSON.

## Что проверено

Автоматически:

```bash
npm test
npm run typecheck
npm run build
```

В браузере вручную проверены:

- создание ручных и расчётных метрик;
- создание связи перетаскиванием на Canvas;
- автоматическая связь из формулы;
- сохранение расчёта при переименовании alias;
- запрет цикла;
- Domain many-to-many и сворачивание разделов;
- создание, перемещение и сворачивание Visual Group;
- произвольная North Star;
- восстановление состояния после перезагрузки.
