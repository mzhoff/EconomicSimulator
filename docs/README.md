# Документация EconomicSimulator

## Зачем существует продукт

EconomicSimulator должен помогать продукт-менеджеру отвечать на практические
вопросы:

- из чего складывается ключевой экономический результат;
- какие показатели действительно являются его драйверами;
- что произойдёт при изменении цены, спроса, комиссии, стоимости оборудования
  или другого допущения;
- где находится точка безубыточности;
- какое значение параметра необходимо для заданного срока окупаемости;
- какие допущения являются фактами, а какие — гипотезами;
- куда выгоднее направить ограниченные продуктовые и операционные ресурсы.

Первый реальный кейс продукта — экономика TokBeri. Он используется не как
демонстрационный пример, а как основной полигон для развития движка.

## Как читать документацию

### 1. Предметная модель

[Предметная модель метрик](metric-model.md) объясняет:

- что такое `Stock`, `Flow`, `Rate` и `Event`;
- почему этого типа недостаточно без единиц, времени и grain;
- чем тип поведения отличается от роли `North Star` или статуса `Fact`;
- какие арифметические и агрегирующие операции допустимы;
- как в будущем события будут превращаться в фактические потоки и состояния.

### 2. Большой план продукта

[Продуктовый и технический roadmap](product-roadmap.md) фиксирует:

- целевое назначение продукта;
- архитектурные решения;
- развитие от локальной статической модели к time-series, импорту событий и
  вероятностным симуляциям;
- функции, которые намеренно отложены;
- идеи, которые можно адаптировать из существующих продуктов и open source.

### 3. Первый этап

[TokBeri Foundation](phase-1-tokberi-foundation.md) — конкретный план первой
реализации. Он ограничивает объём работ и содержит критерии, по которым можно
однозначно решить, что этап завершён.

## Термины

| Термин | Простое объяснение |
|---|---|
| Metric Definition | Каноническое описание показателя |
| Metric Instance | Использование показателя в конкретной модели |
| Calculation DAG | Граф точных формул без циклов |
| Influence Graph | Карта предположительных причинных связей |
| AST | Структурированное представление формулы, пригодное для проверки и сохранения |
| Grain | На каком уровне детализации существует значение |
| Scenario | Набор переопределений относительно базовой модели |
| Actual | Фактическое значение из подтверждённого источника |
| Assumption | Рабочее допущение модели |
| North Star | Выбранная главная метрика конкретного анализа |

## Статус

Документы описывают целевое направление и первый этап. Они не означают, что вся
описанная функциональность уже реализована в текущем прототипе.
