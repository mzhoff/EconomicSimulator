# Monthly Timeline: помесячная окупаемость

## Что реализовано

Текущая денежная модель остаётся обычным месячным `Snapshot`: она один раз
рассчитывает доходы, расходы и итоговый денежный `Flow`, например прибыль за
месяц.

`Monthly Timeline` повторяет этот результат по выбранному количеству месяцев и
учитывает календарь капитальных вложений. Это минимальная временная модель для
планирования возврата инвестиций, а не универсальный Stock/Flow-симулятор.

На Canvas два режима отделены исполняемыми фреймами:

- `Snapshot · 1 месяц` — исходная модель денежного потока;
- `Timeline · N мес.` — накопительные результаты и план CAPEX.

## Расчёт

Для каждого месяца runtime считает:

```text
Накопленный CAPEX(t)
  = Накопленный CAPEX(t-1) + Плановые вложения(t)

Накопленный денежный поток(t)
  = Накопленный денежный поток(t-1) + Месячный Flow

Баланс проекта(t)
  = Накопленный денежный поток(t) - Накопленный CAPEX(t)
```

Три результата отображаются как `Stock`, потому что они сохраняют историю
предыдущих месяцев:

- накопленный CAPEX;
- накопленный операционный денежный поток;
- баланс проекта.

Первая окупаемость — первый месяц с неотрицательным балансом после появления
CAPEX. Устойчивая окупаемость — первый месяц, после которого баланс больше не
уходит в минус. Эти даты могут различаться, если после первого выхода в плюс
запланирована новая закупка.

## Что сохраняется

В `localStorage`, JSON-экспорт и историю undo/redo попадают:

- границы и режимы фреймов;
- источник месячного денежного Flow;
- горизонт расчёта;
- месяц, сумма, название и комментарий каждого планового вложения.

Помесячные точки графика не сохраняются. Они пересчитываются из актуальной
модели, поэтому не могут устареть относительно изменившейся прибыли.

## Сознательные ограничения этапа

- месячный Flow пока одинаков во всех месяцах;
- будущие вложения задаются готовой суммой;
- нет вероятностной вариативности;
- нет налогового и бухгалтерского учёта;
- амортизация намеренно нигде не применяется;
- нет физической Stock/Flow-сети батарей и станций.

Следующий разумный шаг после проверки этой версии — позволить задавать
помесячные значения отдельных входных метрик, не меняя базовый контракт
Snapshot и Timeline.
