# Phase 2: Universal Model Builder

## Цель

Дать пользователю возможность с пустого Canvas вручную собрать статическую
алгебраическую модель без редактирования TypeScript.

Phase 2 не добавляет time-series, Events, рекуррентные Stock/Flow-переходы,
backend или произвольный исполняемый код.

## Минимальная метрика

Пользователь работает с четырьмя типами поведения:

- `Stock`;
- `Flow`;
- `Rate`;
- `One-off`.

Узел содержит:

```text
id          скрытый стабильный идентификатор
name        отображаемое название на любом языке
alias       уникальное техническое имя snake_case
behavior    Stock | Flow | Rate | One-off
unit        единица измерения
value       моделируемое значение
min / max   допустимый диапазон ручного ввода
formula     опционально
domainIds   ноль или несколько смысловых доменов
description опционально
position
```

Формула является атрибутом узла:

- формулы нет — значение редактируется вручную;
- формула есть — значение вычисляется и ручной ввод блокируется.

`Observed`, `Target`, `Input`, `Formula` и `Event` не являются типами метрик.
North Star также не является типом или ролью — это текущая, необязательная цель
анализа.

## Alias и формулы

Отображаемое название и технический alias независимы:

```text
name:  Средний чек
alias: average_check
```

Alias уникален внутри модели и соответствует:

```regex
^[a-z][a-z0-9_]*$
```

Пользователь может создать расчётную зависимость двумя способами:

1. протянуть Calculation-связь на Canvas — это откроет Formula Composer и
   добавит исходную метрику;
2. ввести alias в Formula Composer — после сохранения Canvas автоматически
   построит связь.

AST хранит стабильные metric ID, поэтому безопасное переименование alias не
ломает зависимости.

Первая версия Formula Composer поддерживает числа, aliases, скобки и операции
`+`, `−`, `×`, `/`.

## Визуальный язык Calculation

Calculation остаётся сплошной линией. Цвет показывает локальное направление
влияния при текущих значениях:

- зелёный — положительное;
- красный — отрицательное;
- серый — нулевое;
- янтарный — динамическое или неопределённое.

Небольшой badge показывает структурную операцию: `+`, `−`, `×`, `÷` или `ƒ`
для смешанного пути. Influence остаётся пунктирной связью и не участвует в
вычислении.

## Карточки

| Behavior | Размер | Скругление |
|---|---:|---:|
| Stock | 272 × 272 | стандартное |
| Flow | 272 × 112 | стандартное |
| Rate | 224 × 88 | на один шаг больше |
| One-off | 248 × 104 | ticket-стиль |

Создание и редактирование выполняются в центральном модальном Node Editor,
чтобы форма оставалась в фокусе поверх контекста Canvas. Выбор поведения
показывается четырьмя видимыми карточками, а не dropdown.

## Domain и Visual Group

Это независимые способы организации.

### Domain

Смысловая классификация many-to-many:

- метрика может относиться к нескольким доменам;
- домены пользователь создаёт сам;
- разделы доменов сворачиваются в боковой панели;
- домены используются для фильтров и будущих таблиц;
- одна и та же метрика в разных разделах остаётся одним узлом.

### Visual Group

Геометрический контейнер на Canvas:

- рамка и название;
- совместное перемещение;
- сворачивание;
- создание из текущего выделения;
- переименование и разгруппировка;
- не влияет на расчёт или Domain.

В первой версии узел находится максимум в одной Visual Group.

## Надёжность

- cycle prevention до сохранения формулы;
- unit/behavior validation;
- alias uniqueness;
- `min <= value <= max`;
- ошибка вычисления при фактическом делении на ноль;
- undo/redo изменений модели;
- миграция v1 с backup;
- autosave, несколько моделей и JSON round-trip.

## Проверочный сценарий

С пустого Canvas:

1. создать `rentals` (`Flow`);
2. создать `average_check` (`Rate`);
3. создать `revenue` (`Flow`) с формулой
   `rentals * average_check`;
4. создать `infrastructure_costs` (`Flow`);
5. создать `profit` (`Flow`) с формулой
   `revenue - infrastructure_costs`;
6. увидеть зелёные `×`/`+` и красную `−` Calculation-связи;
7. назначить несколько Domain;
8. создать Visual Group;
9. выбрать любую метрику целью анализа;
10. перезагрузить, экспортировать и импортировать модель без потери структуры.
